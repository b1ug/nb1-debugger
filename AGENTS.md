# nb1 Embedded Workbench

- Maintain source in `src/`; `dist/` is generated. Never edit dist manually.
- Use Action, Sequence, Step, Job, Pattern and DeviceSequence terminology and the confirmed API v1 contracts. Keep protocol behavior explicit when changing presentation.
- Public documentation and developer instructions default to English, with a corresponding Chinese README and explicit bilingual Web UI. Web tools default to English and offer explicit Chinese (zh-CN) selection through the shared, extensible locale catalog. Never infer Chinese from OS/browser settings. Preserve user-authored text, records, server payloads, Job IDs and canonical API/color values during language changes.
- Serve all runtime assets locally. Do not add a CDN, remote font, analytics, Service Worker, or startup download.
- The API and embedded page share an origin. Explicit offline previews show simulated data and must not imply a connected device.
- Editing forms and previewing never execute a light task. Only explicit playback/stop uses execution APIs. Retain a known Job ID after an uncertain submission and query its status. An absent record leaves the outcome unknown. The user decides any subsequent run.
- Nightlab in `design-nightlab` is the approved appearance. Reuse its semantic tokens, composition, controls, full 3D light field, corrected enclosure and two-face fallback faithfully. A visual deviation requires a separate justification and user approval before implementation; relative paths, closed asset contracts, bundling, storage encoding and real-data adapters are necessary integration work.
- Preserve the approved mascot/icon, raw CAD, engraving, source provenance and licenses. Keep `*.stl binary` so Git cannot normalize the protected source geometry. LED 1 is the blink(1) wordmark face; LED 2 is ThingM, independent of camera pose.
- Keep draft targets, screen playback, cached device readback and Job state distinct. Cached readback is not a per-command acknowledgment or optical measurement. Do not import software review runtimes, fake HID, software identities, hidden ownership confirmations or simulated backends into production.
- The embedded schema v2 manifest binds stored and decoded bytes separately. Keep the exact asset inventory, deterministic gzip, canonical style nonce and reviewed stored/decoded/base budgets aligned with the host importer. Do not weaken integrity or CSP to make an asset pass.
- Preserve keyboard focus, labels, aria state, mobile layout, and reduced motion. Warm styling must keep errors and stop actions clear.
- This public source tree must contain no personal paths, private notes, device serials, internal acceptance records, development screenshots or rejected artwork. Hardware acceptance belongs outside this repository. Preserve the approved visual language, raw CAD/brand/license bytes and the closed bundle inventory.
- Use only the approved mascot in `brand/nb1-mascot.png` and its production derivatives. Keep selection galleries, rejected drafts, prompts and generation records outside this repository. Derive favicons from the approved artwork; do not redraw an alternative character.
- The JSON editor uses a pinned, minimal CodeMirror build. Keep raw JSON text unchanged except for explicit whitespace formatting; local syntax diagnostics do not establish Sequence validity. Preserve the plain-text fallback, composition input, Undo history and keyboard focus. Editor-generated styles use the page nonce; never loosen CSP to unsafe-inline or load a CDN.

- Play validates the current captured draft internally; a manual Screen preview is optional. Solid separate LED colors use the existing serial Sequence with two zero-fade, zero-hold Steps in one operation/Job, never a new Action or physically atomic USB promise. Capture device/draft identity across validation, submit the canonical result, and never retry an unknown outcome automatically.

- Derive persistent playback blockers beside Play from retained Job state; draft edits, device refresh and optional Preview must not erase an unresolved or active Job explanation. A restored unresolved ID may be queried read-only, never automatically resubmitted. Preserve a validated saved terminal outcome; scope late query results and errors to their captured task identity.

- Uncertain current Jobs reconcile only through bounded read-only GETs for the original ID: up to three retries at 1, 2 and 4 seconds after transient lookup failures. Stop automatic checks on missing records or unverified responses, and keep manual recovery visible. A new explicit status check may start a fresh bounded read episode. Never retry a Job POST; cancel or invalidate timers and in-flight callbacks on task/lifecycle changes.

- User-authorized Color sets are local authoring data: browsing only changes offered swatches; explicit pair fills current color slots and Create Sequence opens an editable serial template. Never change execution, save automatically, add Action/API aliases, or alter the Nightlab chrome. Keep the shared catalog/chooser byte-identical with the browser workbench.

- All eight curated themes contain exactly eight literal Hex6 values, stored in the common editorial hue order. Keep the nine-swatch common-color utility outside the theme grid; preserve its values/order, expose it through get(essentials), and reject sequence(essentials). Freeze an explicit `pair` separately and use it for pair application, preserving target/LED order. The user-authorized read-only hue comparison uses static category metadata, repeats identical recipes and never edits forms, changes Screen playback, or performs I/O. Keep comparison styles in the shared adapted block; do not infer device colorimetry from hue columns or input differences.
